dispatchSetState Eager Bailout — Legacy vs Concurrent

Bug: setState(sameValue) inside useLayoutEffect gets an eager bailout (1 render) in legacy mode but a lazy bailout (2 renders) in concurrent mode.

Root cause: In dispatchSetState, the eager bailout checks fiber.lanes === NoLanes && (alternate === null || alternate.lanes === NoLanes). During useLayoutEffect in concurrent mode, this check fails — residual lane bits remain on the fiber or alternate that the legacy pipeline clears. 
// dispatchSetState — ReactFiberHooks.js
if (fiber.lanes === NoLanes &&
    (alternate === null || alternate.lanes === NoLanes)) {
  const eagerState = lastRenderedReducer(currentState, action);
  if (is(eagerState, currentState)) {
    enqueueConcurrentHookUpdateAndEagerlyBailout(...);
    return; // ← NO re-render (eager bailout)
  }
}
// Falls through → scheduleUpdateOnFiber → lazy bailout (extra render)
